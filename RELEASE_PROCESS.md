# Release Process

**Module:** `core/release/release_manager.py`  
**Manifest:** `data/release/release_manifest.json`

## Version management

Runtime version from `build_info.py` (generated by `scripts/generate_build_info.ps1`):

- `BUILD_VERSION`
- `BUILD_TYPE` (`dev`, `beta`, `consumer`, `owner`)
- `BUILD_DATE`

`GET /api/version` exposes version metadata.

## Pre-release checklist

1. Generate build info:
   ```powershell
   .\scripts\generate_build_info.ps1 -Version "1.0.0-beta.1" -BuildType beta
   ```
2. Verify build:
   ```bash
   python run_beta_validation.py
   GET /api/release/verify
   ```
3. Generate manifest:
   ```bash
   POST /api/release/manifest  {"channel": "beta"}
   ```
4. Build artifacts:
   - `scripts/build_both.ps1` or CI `.github/workflows/build.yml`
   - `desktop-shell`: `npm run dist`
5. Publish GitHub Release with:
   - Tagged version `vX.Y.Z`
   - Installer/asset + SHA-256 in release notes
   - Mark prerelease for **beta**, release for **stable**

## Changelog

- Prefer `CHANGELOG.md` at repo root
- Fallback: `GET /api/release/changelog` uses `git log --oneline`

## Beta distribution

1. Ship **beta** channel builds to testers
2. Auto-updater checks GitHub on boot
3. License: `BUILD_TYPE=beta`, `TRIAL_DAYS` or server `beta_expires_at`
4. Restricted mode after expiry — activate license, no file deletion

## Update metadata

Manifest includes `update_metadata.github_repo` and supported channels for the updater and Electron `dev-app-update.yml` alignment.
